0How to use this document

These are two separable contracts. Part I can be satisfied without ever implementing PACT — it defines a non-stationarity that any method can be measured against. Part II can be satisfied at zero severity, on an environment's own native coupling. You need both only if the claim is that a method handles injected drift better than baselines do.

Requirement IDs are stable and referenceable. MUST marks a property whose violation invalidates the resulting numbers; SHOULD marks a default you may depart from if you say so in the ablation table. Where the source implementation gates a requirement with an executable test, the test name is given — port the test, not just the prose.

The one-sentence version. A non-stationarity is only evidence if it switches itself off in a regime you can point to, reaches every arm through the same object, and is anchored to a number someone else published. A method is only credible if it cannot do worse than the baseline it wraps, and if the quantity it claims to identify is scored separately from the quantity it claims to win on.

Part I

The non-stationarity form

A specification for injected drift that a domain expert would recognise as physics rather than as an experimental knob.

I.1The four objects

Every conforming instance supplies exactly four things. Three of them should already exist in the domain's own literature; if you find yourself inventing more than one, the domain is probably the wrong choice rather than the spec being wrong.

NS‑1.1

MUST — A medium with a loading ratio. A scalar per agent measuring how close the shared resource is to its limit along that agent's path through it.

u_i = max over elements a used by i of load_a / (capacity_a · g)

The aggregation MUST be a maximum over the agent's own elements, not a mean. Congestion is a property of the worst element; averaging over dozens dilutes the signal toward zero. In the source implementation, switching this sensor from mean to max on the POWER instance raised applied compensation sixfold at otherwise identical settings.

gated by test_sensor_uses_the_binding_link_not_the_mean
NS‑1.2

MUST — A declared coupling operator W. How much one unit of agent j's activity loads the elements agent i depends on. Written down from the environment's structure, never fitted from run data.

Op[a, j] = 1[element a is used by j] / capacity_a W[i, j] = mean over a ∈ E(i) of Op[a, j] for j ≠ i W[i, i] = 0 ← asserted, not argued

W MUST have a zero diagonal, weights spanning orders of magnitude, and measurable asymmetry. A flat geometric proxy — "peer touches something I touch" versus "everything else", equal weight inside each bucket — is NOT acceptable: in the source implementation it measured a fit gain of −0.0045, meaning the peer channels predicted worse than an intercept-only null.

gated by test_operator_is_zero_diagonal, test_operator_is_asymmetric_and_spread
NS‑1.3

MUST — An exogenous driver A(t). A slow signal, a function of observable time alone, that no agent's action can influence. It reaches the agents only by shrinking capacity, never by adding a term to the loss.

Weather is the reference instance for traffic; ambient temperature is the counterpart for power. The requirement is not that it be weather — it is that a domain practitioner names it without prompting when asked "what makes this harder some days than others, that nobody here controls?"

NS‑1.4

MUST — A harm channel. The map from reduced capacity to worsened reward, expressed through the environment's own performance function so the reward function is untouched. The agent is still paid exactly what it was paid before; the quantity it is paid for is simply worse because the medium delivered less.

MUST NOT subtract a penalty term. A penalty is a changed objective, and every comparison against a stock baseline then measures the objective change rather than the physics.

NS‑1.5

SHOULD — A compensation channel with a known inverse. If one exists, the form is strictly richer: the method can be asked to cancel the harm rather than merely route around it. Its absence does not disqualify the environment, but it MUST be declared, because it decides whether the method's exact-compensation claim transfers (see II.6).

A compensation channel is normally loop-coupled: exercising it changes the medium it compensates against. In traffic, shifting departure time changes who you share the road with, so a uniform shift accomplishes exactly nothing and only a differential one helps. Say so explicitly; it is the commons in miniature.

I.2The category‑C signature

This is the property that separates a coordination problem from a difficulty knob, and it is the single most important thing to get right when porting.

harm_i = f( u_i under derated capacity ) / f( u_i at nominal capacity ) u_i = 0 ⟹ harm_i = 1 EXACTLY — a lone agent is untouched, at any severity g = 1 ⟹ harm_i = 1 EXACTLY — no severity, or a placebo day

Because capacity sits in the denominator of the loading ratio, the driver multiplies every peer's contribution and leaves the solitary agent's term at zero. The disturbance is therefore an amplifier on the cross-agent coupling, not a level shift added on top of it.

The practical test: an agent alone in the environment must read a harm of exactly 1.0 in the worst storm you can dial. If a single agent suffers, the driver is adding to the loss somewhere and NS‑1.4 is violated.

With a linear performance function this reads especially plainly. For f(u) = 1 + αu and small u, the harm is ≈ 1 + α·u_i·(1/g − 1): peer load times a weather factor. Nothing an agent can learn to absorb alone.

gated by test_n1_gives_exactly_zero_peer_load, test_harm_is_identity_when_the_dial_is_off

I.3The severity dial

A single scalar σ scales the driver's effect. Its four requirements exist because each one closes a specific way of accidentally rigging a result.

NS‑2.1

MUST — Identity at zero, exactly. At σ = 0 the capacity multiplier is 1.0 bit for bit, at every driver value, so the stock task is recovered byte for byte and the same command produces the no-severity row. Not "approximately"; equality, tested over the whole driver domain.

gated by test_dial_identity_at_zero_is_exact
NS‑2.2

MUST — Monotone in σ at every driver value, not merely at the peak. A dial that is harsher at σ=1 than σ=2 anywhere in its domain is not a severity ordering.

gated by test_dial_is_monotone_and_never_generous
NS‑2.3

MUST — Never generous. The multiplier is ≤ 1 always. This closes the uprating trap: a two-sided physical law scaled by σ made the POWER task strictly easier at σ = 2 in the source implementation. Keep only the harmful half of a symmetric law.

NS‑2.4

MUST — Anchored at σ = 1 to a published constant. Not a round number you chose. The reference instance uses the Highway Capacity Manual's heavy-rain capacity adjustment factor: capacity falls to ≈0.86 of dry, so the loss at σ=1 is 0.14. Every σ > 1 MUST be labelled a beyond-physical stress test everywhere it appears, including in figures.

gated by test_dial_anchored_to_hcm
NS‑2.5

MUST — A placebo regime. Part of the driver cycle where A(t) is exactly zero, so the dial is provably inert there for every σ and the whole sweep is byte-identical in that regime.

This is the cheapest credibility you will ever buy. A reviewer alleging a rigged knob then has to explain why the rig switches itself off half the time — and the placebo comes free from NS‑2.1 the moment the driver is built to reach exact zero rather than merely small values.

gated by test_placebo_regime_is_exactly_inert, test_dry_season_produces_no_excess_to_attribute

Reference driver

The form used in the reference instance. A smooth bump that starts and ends at exactly zero, over a fixed period, with the remainder of the cycle identically dry:

φ = (t mod P) / P A(t) = sin²( π · min(φ/w, 1) ) if φ < w, else 0 P = 100, w = 0.5 g_a = clip( 1 − σ · L · A(t) · s_a , lower 1e‑3 , upper 1 ) L = 0.14

The per-element sensitivity s_a (mean 1, clipped to [0.4, 2.0]) makes the derating facility-specific, as published capacity adjustment factors are. It matters more than it looks: a uniform derating leaves the binding element unchanged at every severity, which makes the ceiling decomposition σ‑invariant and hides the very effect you are trying to show.

I.4Layering: severity is task physics

NS‑3.1

MUST — The dial sits below the method in the class hierarchy, and is read from the task configuration, never from a method's own block.

Environment └── SeverityEnvironment ← every baseline gets this, unmodified └── Method ← adds the compensator only

A dial only the method's arm experienced is worthless as evidence. The corollary is an implementation rule: apply the harm at the single place every host reads a reward, not in a training loop that only some hosts have. In the reference instance the on-policy scripts and the replay-buffer scripts share exactly one such point, and the wrapper hooks that.

NS‑3.2

MUST — Harm the records as well as the rewards. Every downstream metric, plot and estimator reads the logged trajectory, not the reward stream.

This is not a hypothetical. In the source implementation a non-learning baseline scored identically at σ=0 and σ=3 to six decimal places — impossible unless the dial never reached the metric. Reward, record and metric must describe the same episode.

NS‑3.3

MUST — Fail loudly when the layer cannot be built. Count untouched rewards, count harmed records, and print both at the end of every run with an explicit refusal to report the run as a severity arm if either is zero.

A silently inert disturbance is the one failure mode that is indistinguishable from a clean null result — in exactly the arm you most need to trust.

NS‑3.4

SHOULD — The driver's clock persists across episodes. Weather does not reset because a training episode ended. Latch the day the harm was computed for, not the counter, when reporting diagnostics: an off-by-one there misaligns the entire placebo column.

I.5The ceiling decomposition — compute this first

This is the highest-value hour in the whole project, and it runs with no policy, no training and no simulator. Do it before writing method code; committing the output first is what makes it a prediction rather than a post-hoc explanation.

Under the dial each agent's loading exceeds its σ=0 counterfactual by Δ_i = u_i·(1 − g). Every unit of that excess traces to a contributor, and contributors partition by who can move them:

Δ_fixed load from participants no agent controls humans, background demand Δ_own the agent's own unit, amplified by 1/g Δ_peer other controllable agents, through W, by 1/g irreducible = Δ_fixed / Δ_total decentralized ceiling = 1 − Δ_fixed / Δ_total non-coordinating ceiling = 1 − (Δ_fixed + Δ_peer) / Δ_total COORDINATION GAP = Δ_peer / Δ_total ← what the method claims

Excess is proportional to load, so a contributor class's share of the load is its share of the excess — the attribution is exact, not heuristic. Compute it by re-running the loading function with one class of contributor at a time.

NS‑4.1

MUST — Compute and commit the decomposition before any method code exists. If the coordination gap is small, this environment is a poor showcase; say so and pick another. Retuning after seeing a method underperform plants the problem.

gated by test_ceiling_shares_are_a_partition, test_coordination_gap_grows_with_fleet_share, test_all_machine_fleet_has_no_irreducible_share
NS‑4.2

SHOULD — Report the gap against controllable share. The prediction that it rises with N is one no competing credit-assignment method makes, and it costs no training to test.

Part II

PACT‑1

Online identification of a cross-agent coupling from each agent's own proprioceptive residual, with reliance on the estimate learned from return.

II.1The reduction

The whole method rests on collapsing an N-agent, many-element coupling into a handful of parameters that do not scale with either.

y_i(t) = β*(t) · ψ_i(t) , ψ_i = [ 1, x_1, …, x_r ] x_m,i = Σ_{j ≠ i} O_ij · G_m[ path(i), path(j) ] exact arithmetic, no estimation

Read that as: project the unknown per-element sensitivity field onto r known element classes. The classes are public infrastructure — a road's lane count and speed limit are painted on it. What is not handed over is β*: how much a peer unit on each class actually costs today. That drifts as the operating point moves along the performance curve, and must be tracked online.

P‑1.1

MUST — r is independent of the number of agents and of the number of elements. If your candidate reduction has a parameter per agent or per element, it is not this method.

P‑1.2

MUST — Know the model class, estimate the parameters. The basis is declared from environment structure that exists before training. Inventing the basis alongside the coupling — which is what a synthetic benchmark lets you do — makes the identification claim vacuous.

II.2The sensor

P‑2.1

MUST — The target is the agent's own relative excess over its own nominal, and nothing else:

y_i = clip( realized_i / nominal_i − 1 , −1 , y_clip ) y_clip = 10, declared

This is proprioception, not privilege: every participant knows how long its own operation took and what it would have cost on an empty medium. Relative rather than absolute removes path-length scaling and matches the performance function's own form.

MUST NOT use any quantity an agent could not physically observe. MUST report clip_frac; the clip bounds outliers that would otherwise dominate a least-squares fit, and it is a declared constant, never tuned toward a curve.

gated by test_relative_excess_and_clip

II.3The basis

P‑3.1

MUST — Zero-diagonal. Every channel excludes the agent's own contribution, so the sum is strictly over j ≠ i. A lone agent must read exactly zero on every channel. This is the same signature as I.2 and is what makes the estimated quantity a coupling rather than a self-effect.

gated by test_basis_zero_diagonal_and_N1, test_basis_waveform_arithmetic
P‑3.2

MUST — Verify a vectorised implementation against a brute-force loop written straight off the definition, at startup, and abort on mismatch. Index order and self-exclusion are exactly the kind of wiring bug that leaves every diagnostic looking healthy.

P‑3.3

MUST — Centre and scale the regressor on a geometric reference. Compute the load each agent would see if every peer acted uniformly at random — a function of structure and schedule only, so no run data enters — and centre on that.

Measured in the source implementation: raw channels carried a large common mean against an intercept column of 1, giving a design-matrix condition number ≈1.3×10⁵. The intercept and the class channels then trade off and the split becomes unidentifiable even though prediction is fine. Centring dropped it to 24 (class-segregated) and 336 (class-mixed), and moved β recovery from unidentifiable to 0.001 / 0.012 error.

gated by test_end_to_end_recovers_a_known_congestion_law, test_mixed_class_city_is_harder_but_still_identifiable
P‑3.4

MUST — Prune degenerate channels (below a declared share of the medium, or below a declared variance) and keep every downstream index aligned when you do. MUST verify that the basis's ordering of options matches the environment's own — a permuted order points every channel at the wrong element while looking perfectly healthy.

gated by test_channel_pruning_keeps_everything_aligned, test_channel_variation_flags_a_constant_channel

II.4The estimator

Per-agent recursive least squares with a forgetting factor, one row per agent per step: its own realized residual against the channels of the option it actually took.

K = P φ / ( μ + φᵀ P φ ) β ← β + K ( y − φᵀ β ) P ← ( P − K (Pφ)ᵀ ) / μ , then symmetrised μ = 0.999 p₀ = 10.0 declared; sweep, never tune
P‑4.1

MUST — Decentralized. Agent i never sees another agent's residual. It sees only peers' executed actions, which a connected fleet broadcasts anyway.

P‑4.2

MUST — Skip rows whose regressor is numerically zero. A dead row carries no information about β but still divides P by μ, inflating the covariance every step and silently tightening the effective forgetting factor. This is covariance windup, and it makes μ stop meaning what your banner says it means.

gated by test_rls_dead_row_does_not_inflate_covariance
P‑4.3

SHOULD — Treat μ as the bias/variance dial of a tracking floor of order √(noise · drift). It cannot be tuned away, only balanced. Declare it, sweep it in the ablation, and never present a swept value as a default.

gated by test_rls_recovers_known_beta, test_rls_tracks_drift

II.5Trust

g = g_max · sigmoid( w + bias ) , EMA-smoothed, gated by confidence bias = 2.2 ⟹ w = 0 sits at 0.90 · g_max
P‑5.1

MUST — Invert the prior. Start near full reliance, not at half. The estimator already supplies the magnitude, so this knob tracks nothing: whenever the estimate is right, optimal trust is a constant. Initialising at half starts at half of a known-correct answer and asks a weak, noisy policy gradient to walk uphill to it.

Measured in the source implementation on the Ant instance: over 10M steps trust drifted 0.485 → 0.444 while the estimate's cosine similarity to truth sat at 0.99 — the entire budget spent at half compensation with a correct waveform. Return 3642 against 5444 for the inverted prior.

gated by test_trust_prior_is_inverted
P‑5.2

MUST — Gate reliance on prediction uncertainty, not on the trace of the covariance:

conf = 1 / ( 1 + r · ψᵀPψ / ( p₀ · ‖ψ‖² ) )

The compensator only ever uses the scalar β̂·ψ, so the uncertainty that matters is that scalar's. Directions the data never excites are also directions the prediction never uses.

The trace version is a trap. tr(P) is dominated by the least excited direction, and RLS with forgetting inflates exactly those without bound — so once the fleet converges and actions stop varying, tr(P) grows even though prediction stays perfect, and the gate quietly disarms a working compensator. Measured: confidence fell 0.20 → 0.005 over 4200 steps while fit R² sat at 0.9998, taking applied trust to 0.003 and reducing the arm to the plain baseline.

gated by test_confidence_cold_to_warm, test_pred_confidence_survives_dead_excitation
P‑5.3

MUST — Report policy-set trust and applied trust as separate columns. They diverge precisely when the confidence gate is misbehaving, which is the failure above.

II.6The channel: does exact compensation transfer?

This is the porting decision that most changes what you can claim, and it must be settled before any code is written.

Environment propertyChannelWhat you may claim
An additive, invertible harm. The disturbance enters the same space as an action, so it can be subtracted off. Exact channel inverse. Compensation restores the stationary game. Identification and compensation.
No inverse. The harm is a property of a shared medium and no action cancels it — you cannot subtract minutes off a congested road. Trust-weighted prior over discrete options. The estimator ranks; trust decides how hard the ranking bites. Identification and steering only. Say this plainly in the paper.

The substitute channel used in the reference instance, where no inverse exists:

z_k = zscore over the agent's valid options of predicted cost_k logits_k = logits_k − g · κ · z_k κ = 1.0, declared
P‑6.1

MUST — Make the shift dimensionless. The z-score is what lets κ be a single declared constant rather than a per-instance scale factor that would need tuning — and a tuned κ is a tuned result.

gated by test_steer_direction, test_steer_degenerate_cases
P‑6.2

MUST — Reach the trust parameter through the existing objective, with no new sampled dimension and no extra log-probability term. Because the shift sits inside the softmax, log π(k|s) = log softmax(logits − g(w)·κ·z)_k already depends on w, so the ordinary policy gradient flows into it. The host's clipped surrogate, entropy bonus and optimiser stay byte-for-byte unchanged — an arm difference must not be able to be an algorithm difference.

gated by test_policy_runs_and_trust_head_receives_gradient

II.7The floor property

P‑7.1

MUST — At g = 0 the method returns the untouched host policy exactly — bit for bit, for any β̂, however wrong — and the same must hold when all predicted values are identical, where the shift is defined to be zero rather than NaN.

The estimator therefore sits entirely outside the worst-case decision path. A diverging estimate can fail to help; it cannot drag the arm below the baseline it wraps. This is the property that makes the method safe to propose, and it is cheap to hold only if you gate it — so gate it, before a single episode is simulated, in both the numerical and the differentiable implementation.

gated by test_floor_property_is_exact, test_blind_arm_is_exactly_the_untouched_policy, test_torch_numpy_parity

II.8The compensation commons

Steering onto the option the model says is cheap is exactly what loads that option. This is Wardrop/Braess in traffic, and it is a general property of any medium-mediated coupling: the compensation feeds the thing it compensates against.

P‑8.1

MUST — Log the externality, and MUST NOT act on it. A concentration index over the fleet's choices (normalised Herfindahl, 0 = perfectly spread, 1 = everyone on one option) plus the fraction of agents that switched option. Rising concentration alongside rising trust is the externality becoming visible.

Acting on it would make the method a mechanism rather than a per-agent estimator, and would break the decentralization claim of P‑4.1.

gated by test_herd_index_bounds

II.10The instrument panel

One row per step. The design principle: keep "is the method working" and "is it winning" in separate columns, because the method can work perfectly and still not win, and that is a statement about how much headroom the domain has — not a bug.

High fit with low prediction is a finding, not a bug. It says the physics is right but the population is changing faster than your forecast smoother can track. Keeping the two columns apart is what stops a bad number being blamed on the wrong thing.

Part III

Porting to a new environment

Answer the questionnaire before writing code. Two of these questions can disqualify a domain outright, and finding that out on day one is worth more than any of the engineering that follows.

III.1Feasibility questionnaire

  1. Is there a shared medium with a published capacity? You need a denominator that a practitioner would recognise and a number they would defend. No medium, no method — the coupling has nowhere to live and the operator has nothing to divide by.
  2. Can you write down W from structure, before any run? Incidence over capacity, or the domain's equivalent sensitivity matrix. If you can only fit it, stop: a fitted operator makes the identification claim circular, and the flat-proxy fallback is measurably worse than nothing.
  3. Does each agent observe its own realized-versus-nominal outcome? Proprioception, not privilege. If the residual is only available centrally, the decentralization claim goes — you may still run the method, but say so.
  4. Is there an exogenous driver a practitioner names unprompted? Ask them: "what makes this harder on some days, that nobody here controls?" If the honest answer is "nothing", you have no NS to inject and Part I does not apply — but Part II still can, on the environment's native coupling at σ = 0.
  5. Does the harm have an inverse? Decides whether you claim compensation or only steering (II.6). Both are publishable; conflating them is not.
  6. What is the coordination gap? Compute it before writing method code. A small gap means the environment is a poor showcase — that is a result about the domain, and reporting it costs you an hour instead of a month.
  7. Is the medium loaded enough for a capacity loss to matter? Check the loading distribution. A medium sitting far below its limit cannot express the disturbance however large σ grows — and this determines your performance function's exponent (see below).
Regime, not convention

Take the performance function's exponent from the operating regime you measured, not from the textbook. The classic traffic coefficients (α=0.15, β=4) are calibrated near capacity; the reference instance runs two orders of magnitude below it, where a quartic term is numerically dead — a 14% capacity loss at v/c = 0.2 would change the outcome by 0.02%.

In the low-utilisation regime the correct form is linear: queueing delay is ρ/(1−ρ) ≈ ρ for small ρ. Then calibrate the single coefficient once against an observable and state the one-line procedure — here, mean realized/nominal − 1 = 0.50 divided by mean loading 0.219, giving α = 2.28. That is a stated procedure against a measurement, not a knob turned toward a result, and it belongs in the ablation table either way.

An environment with a genuine native coupling and no plausible exogenous driver is still a perfectly good testbed for identification — you run everything at σ=0 and claim the reduction, not robustness to drift. Manufacturing a driver the domain does not have is precisely the self-designed-benchmark critique you are trying to escape.

III.3Build order

Ordered so that the cheapest disqualifying result arrives first. Each step's output is committed before the next begins.

Step 7 is the one people skip and should not. A probe with uniformly random actions is the best case for identification — maximum excitation — so a fit gain near zero there is decisive, and it costs a fiftieth of the full run.

P‑10.1

MUST — Every arm in the comparison is launched through the same entry point, with severity supplied from outside the method. In the reference instance this is a launcher that substitutes the wrapped environment class before the target script imports it, so the baselines are bit-for-bit the ones their authors shipped and the only new object is the environment they run in.

The alternative — editing each baseline to accept a severity flag — makes every one of them a modified baseline, and a reviewer will rightly ask what else changed.
